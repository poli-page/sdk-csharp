---
title: Cancellation
description: How to cancel in-flight requests with CancellationToken.
---

Every async method on the SDK accepts a `CancellationToken`. Cancelling the token aborts the underlying HTTP call, and the SDK throws a `PoliPageException` with `Code == PoliPageErrorCode.Aborted` (message `Request was aborted`, the `OperationCanceledException` as `InnerException`). A cancellation is never retried.

## Pass a CancellationToken

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));

try
{
    byte[] pdf = await client.Render.PdfAsync(
        new RenderInput
        {
            Project  = "billing",
            Template = "invoice",
            Data     = new Dictionary<string, object> { { "invoiceNumber", "INV-001" } },
        },
        cancellationToken: cts.Token);
}
catch (PoliPageException ex) when (ex.Code == PoliPageErrorCode.Aborted)
{
    Console.WriteLine("cancelled by caller");
}
```

The cancellation takes effect at once wherever the call is: during an attempt, during the wait before a retry, or while the PDF is read. A read of the `Render.PdfStreamAsync` stream that is cancelled, through the call's token or the read's own, throws `aborted` too. `OnError` receives the `aborted` error like any other error the SDK throws.

## Cancellation vs request timeout

`PoliPageClientOptions.RequestTimeout` (or `RequestOptions.RequestTimeout` per call) bounds each API attempt: the connection, the answer's headers and its whole body. Your token is composed with it — whichever fires first wins.

When an attempt times out, the SDK records a `timeout` (`Request timed out after <ms>ms`) and retries it per the [retry policy](../retries-and-idempotency/); once the retries are exhausted, it throws `PoliPageException` with `Code == PoliPageErrorCode.Timeout`. The timeout holds whatever `HttpClient` you inject. If that client's own `HttpClient.Timeout` is shorter, it fires first and the message names that bound.

## Download timeouts

`Render.PdfAsync`, `Render.PdfStreamAsync`, `RenderToFileAsync` and `DocumentDescriptor.DownloadPdfAsync` fetch the PDF from its presigned URL on a separate download client (`PoliPageClientOptions.DownloadHttpClient`). The same `RequestTimeout` (or the call's `RequestOptions.RequestTimeout`) bounds that download too, whatever download client you inject:

- `Render.PdfAsync` and `DownloadPdfAsync`: the whole download, the PDF's body included.
- `Render.PdfStreamAsync` and `RenderToFileAsync`: the wait for the storage's answer, then each read of the stream. It is an idle timeout, not a total, so a large PDF read at your pace is never cut off. Before the answer, the call throws; mid-stream, the read throws.

Past it, the SDK throws `PoliPageDownloadException` with `Code == PoliPageErrorCode.DownloadFailed` and the message `Failed to download PDF: timeout` (no status). The download is never retried: call `Documents.GetAsync(id)` for a fresh presigned URL and download again. If the download client you inject has a shorter `HttpClient.Timeout`, it fires first for the wait for the storage's answer, with the same error.

```csharp
try
{
    byte[] pdf = await client.Render.PdfAsync(input, cancellationToken: cts.Token);
}
catch (PoliPageException ex) when (ex.Code == PoliPageErrorCode.Aborted)
{
    // Caller cancellation — never retried.
}
catch (PoliPageDownloadException ex)
{
    // The presigned PDF download failed (timeout, network or storage status).
}
catch (PoliPageException ex) when (ex.Code == PoliPageErrorCode.Timeout)
{
    // An API call timed out after its retries.
}
```

## What `aborted` changes for .NET code

Because a cancellation surfaces as a `PoliPageException`, not as an `OperationCanceledException`:

- A cancelled SDK task ends **Faulted**, not **Canceled**: `task.IsCanceled` is `false`, and code that relies on cancellation semantics (`Task.WhenAll`, `Parallel.ForEachAsync`, `catch (OperationCanceledException)`) sees an ordinary failure.
- ASP.NET Core's exception handler treats an `OperationCanceledException` raised after `HttpContext.RequestAborted` fired as a client disconnect and logs it quietly. A `PoliPageException` is logged as an unhandled error instead, once per disconnect.
- Recognise a cancellation by `Code == PoliPageErrorCode.Aborted`, not by the inner exception's token: the `InnerException`'s `CancellationToken` is the SDK's per-attempt token, not yours.

Where you want the standard behaviour back, catch `aborted` and rethrow an `OperationCanceledException` that carries your token:

```csharp
try
{
    return await client.Render.PdfAsync(input, cancellationToken: cancellationToken);
}
catch (PoliPageException ex) when (ex.Code == PoliPageErrorCode.Aborted)
{
    // The task now ends Canceled, and ASP.NET Core sees a client abort.
    throw new OperationCanceledException(ex.Message, ex, cancellationToken);
}
```

## Example

```csharp
using PoliPage;

var client = new PoliPageClient(new PoliPageClientOptions
{
    ApiKey = Environment.GetEnvironmentVariable("POLI_PAGE_API_KEY")!,
});

using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(10));

try
{
    byte[] pdf = await client.Render.PdfAsync(
        new RenderInput
        {
            Project  = "billing",
            Template = "invoice",
            Data     = new Dictionary<string, object>
            {
                { "invoiceNumber", "INV-001" },
                { "total", 1280 },
            },
        },
        cancellationToken: cts.Token);
}
catch (PoliPageException ex) when (ex.Code == PoliPageErrorCode.Aborted)
{
    // Caller cancellation — never retried.
}
```
